This repository manages Python dependencies through a single-source-of-truth pyproject.toml (PEP 621) paired with a deterministic lockfile, using the uv package manager as the primary toolchain. There is no vendoring; all third-party packages are resolved from PyPI at install time.

### System in use
- Manifest: pyproject.toml declares core runtime deps, build backend (hatchling), and feature flags via [project.optional-dependencies].
- Lockfile: uv.lock pins every transitive dependency with per-platform wheel URLs and SHA-256 hashes, generated by uv. It also records the pillow>=11.3 override that forces Pillow past surya-ocr's pinned <11 constraint.
- Resolver overrides: [tool.uv].override-dependencies is used to force pillow>=11.3 across the whole tree so native AVIF decoding works without the separate pillow-avif-plugin.
- Build system: hatchling builds wheels/sdists; the wheel target ships only src/local_deepl.

### Optional-feature surface
Dependencies are split into opt-in extras so users can avoid heavy ML stacks unless needed:
- web — FastAPI + Uvicorn + websockets for the HTTP server.
- async-translation — Celery + Redis + LangGraph for background translation workers.
- memory — ChromaDB + sentence-transformers for lexicon-backed RAG.
- trocr — Transformers + SentencePiece + safetensors for handwriting OCR specialist.
- nllb — Transformers + SentencePiece for NLLB-200 fast translation fallback.
- quality — sacrebleu for chrF++ scoring.
- comet — unbabel-comet for learned-metric scoring (GPU-preferred).

Core runtime deps include OpenAI client, PyMuPDF, Pillow, Surya OCR, Torch/Vison, OpenCV headless, LiteLLM, httpx, requests (explicitly listed because surya-ocr drops it transitively on newer huggingface-hub), python-docx, and pyspellchecker.

### Dev tooling
A [dependency-groups].dev group (uv convention) lists pytest, pytest-asyncio, ruff, mypy, and pyyaml. These are installed alongside the package when running uv sync --group dev.

### Legacy / auxiliary manifests
- phase2_reqs.txt and phase3_text.txt are narrative planning documents that mention future extras but do not affect resolution.
- .opencode/package.json is an isolated Node workspace for the opencode AI plugin; its @opencode-ai/plugin dep is unrelated to the Python project and lives under .gitignore-ignored cache dirs.

### Conventions developers should follow
1. Declare new runtime requirements in pyproject.toml, never in ad-hoc requirements.txt files. If the dep is large or GPU-bound, wrap it in an optional extra rather than adding it to the core list.
2. Use uv sync --extra <name> to install feature sets; CI and local dev scripts already reference this pattern.
3. Keep uv.lock committed — it is the source of truth for reproducible installs. Regenerate it with uv lock after changing pyproject.toml.
4. Resolve conflicts via [tool.uv].override-dependencies instead of pinning transitive deps directly; the existing pillow override is the model example.
5. Do not vendor packages — the project relies on PyPI wheels and the lockfile's per-platform hash entries for integrity.
