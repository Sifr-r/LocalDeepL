The repository is a single `omniscribe` Python package (`src/omniscribe`) built with Hatchling and exposed as the `omniscribe-server` CLI entry point. All children compose around this package: `tests/` drives it via pytest (with session-scoped fixtures for expensive model loads), while `scripts_and_examples/` provides developer-only CLI helpers that import from `omniscribe.core.*` to build fixtures, run confidence regressions, and visualize results. The root `pyproject.toml` centralises all dependency groups (`web`, `async-translation`, `memory`, `trocr`, `nllb`, `quality`, `comet`, `glossary`) and ruff/mypy rules; `.pre-commit-config.yaml` enforces ruff + uv-lock consistency across every child. `Dockerfile` builds one image bundling both `web` and `async-translation` extras, and `compose.yaml` orchestrates an always-on `api` service plus an optional `worker` (Celery) behind Redis, sharing the same image and environment variables (`LLM_API_BASE`, auth tokens). Cross-child wiring therefore flows through the shared package namespace plus the root build/dev tooling rather than any runtime glue.
