Each file is an independent CLI entry point with no shared module — scripts do not import each other. They share a common pattern: add the repository root to `sys.path`, then import from `local_deepl` (the package under `src/`) and/or third-party libraries (`fitz`, `chromadb`, `surya`, `rich`). The scripts fall into four functional groups:
- Environment/dev tooling: `dev.py` provides `clean` and `doctor` subcommands that check uv, Python ≥3.11, Redis, and an OpenAI-compatible model server.
- Fixture generation & evaluation: `build_fixture.py` runs `PromptedGroundedOCR` against a PDF/image and serializes blocks into the JSON fixture format consumed by `confidence_eval.py`, which orchestrates both `grounded` and `hybrid` pipeline paths against fixtures in `tests/fixtures/` and renders reports via `rich`.
- Debugging & visualization: `debug_detection_only.py`, `debug_image_input.py`, `debug_llm_raw.py`, `inspect_grounded_lines.py`, `inspect_pdf.py`, `visualize_bboxes.py`, `visualize_comparison.py` each target a single diagnostic concern (Surya detection-only boxes, raw LLM output, bbox rendering, PDF inspection).
- Data ingestion: `ingest_lexicon.py` downloads TEI XML files from GitHub, parses them, and upserts entries into a local ChromaDB collection using a SentenceTransformer embedding function.
Dependency direction is strictly one-way: scripts → `local_deepl` package and external libs; there is no internal script-to-script coupling.
