# DocuVerse — OCR & Translation Harness Upgrade

## Goal
Transform the existing `local-deepl` codebase into a top-tier local-first document intelligence harness:
1. Best-in-class handwritten + scanned book OCR.
2. Real document structure reconstruction (block tree, tables, figures, sections).
3. Higher-quality, structure-preserving translation with glossary support.
4. Real structured export (DOCX with real tables/images/headings, HTML with semantic markup, block-tree JSON).
5. (4th priority) Real-time UI feedback with bbox overlay, page thumbnails, streaming text.

The work is split into five phases. Each phase ships a usable, testable increment. The plan assumes Python 3.11+, uv-managed deps, and that the existing two-engine facade (`HybridEngine` + `GroundedEngine`) stays intact — new work is additive and routes through existing extension points.

---

## Phase 2 — Handwriting accuracy: better preprocessing + TrOCR specialist (Weeks 2-3)

**Why second:** Once the UI shows what's being recognized, the user can see immediately where the OCR fails. Handwriting is the headline complaint, so we fix it before the structural pass.

### 2.1 New `HandwritingPreprocessor` (replaces hard-coded binarize)
File: `src/local_deepl/core/preprocessing.py`

Add a new `HandwritingPreprocessor` that runs in addition to the existing `LocalPagePreprocessor`. Steps (in order, all opt-in via a new `handwriting_mode` setting):

1. **Resolution normalization** to 300 DPI (PyMuPDF rasterize at fixed DPI if source is <300, downscale if >600 to bound the TrOCR image dim).
2. **Adaptive binarization** with `cv2.adaptiveThreshold` + Sauvola variant. Add `sauvola_threshold(image)` helper using `cv2` morphological ops (no extra deps).
3. **Stroke-width normalization** via distance-transform on the binary mask + rescale to median stroke width 4px.
4. **Slant normalization** via Radon transform (skimage-free; use a numpy implementation).
5. Optional: per-page classification (printed vs handwritten) via cheap heuristics (ink-density histogram, connected-component aspect ratios) — only handwritten pages go through TrOCR fallback.

### 2.2 TrOCR specialist engine
New file: `src/local_deepl/core/trocr_engine.py`

- Wrap `microsoft/trocr-base-handwritten` and `microsoft/trocr-large-handwritten` via the `transformers` pipeline. Lazy-load on first use, cache the pipeline in a module-level singleton.
- Add a `trocr` optional extra in `pyproject.toml`:
  ```
  trocr = [
      "transformers>=4.45",
      "sentencepiece>=0.2",
      "torch>=2.0",   # already a core dep
  ]
  ```
- Add `trocr_engine=TrOCREngine()` to `OCRPipeline.__init__` extension point (alongside the existing `aligner=`, `ocr_processor=`, etc.).

### 2.3 Hybrid OCR pattern: VLM-first, TrOCR-fallback
File: `src/local_deepl/core/ocr.py`

Following the Extend.ai "specialist + VLM correction" pattern:

```
result = vlm_ocr(image)            # existing
if confidence(result) < 0.75 and is_handwriting_region(result):
    trocr_result = trocr_ocr(crop)
    if trocr_result.confidence > vlm_result.confidence:
        result = trocr_result
    else:
        vlm_corrected = vlm_correct(trocr_result.text)  # VLM re-OCR using TrOCR as a hint
        result = pick_best(vlm_result, vlm_corrected)
```

- Add per-block confidence scoring using cheap heuristics (language-model perplexity via `kenlm` if installed, fallback: word-frequency-based, fallback: length-normalized "looks like a word" check). The threshold (0.75) is a `ConfidenceThreshold` setting.
- The "is handwriting" check is a per-page classifier from 2.1.5; for per-block granularity, use the connected-component + stroke-width signal on each crop.

### 2.4 Better prompts for handwriting
File: `src/local_deepl/core/ocr.py`

- New `HANDWRITING_PAGE_PROMPT` constant that explicitly tells the model: "This may be handwritten cursive. Pay attention to ambiguous ascenders/descenders. Preserve crossed-out words as `[crossed: original]`."
- Add a `handwriting_hint` flag in `ProcessSettings` (in `src/local_deepl/api/schemas/requests.py`) that switches the prompt and enables 2.1-2.3.
- The `dual_engine` path also benefits: use TrOCR as the "draft" instead of Tesseract when the page is classified as handwriting (Tesseract is poor on cursive).

### 2.5 Per-region confidence propagation
Files: `src/local_deepl/core/document.py`, `src/local_deepl/core/workflows/hybrid.py`

`DocumentBlock.confidence` already exists but is never populated. Wire it:

- Grounded backend: take the parser's confidence when present.
- Sparse VLM: use the length-perplexity heuristic.
- Dense VLM: same heuristic on each crop.
- TrOCR: use the model's softmax max as confidence.

Populate the new `block_complete` event (Phase 1.2) with this confidence. The UI's confidence heatmap is just a CSS class per bbox.

### 2.6 New `examples/` test fixture
File: `examples/ground_truth_handwritten_v2.json` (new)

Add ground truth for a second handwritten sample (e.g. a printed handwritten page) so `scripts/confidence_eval.py` can show the improvement numerically.

### 2.7 Tests
- `tests/test_preprocessing.py` for Sauvola binarization + slant correction on a synthetic input.
- `tests/test_trocr_engine.py` for lazy-load, GPU/CPU fallback, confidence extraction.
- `tests/test_handwriting_hybrid.py`: a stub VLM that emits a low-confidence result for a fake "handwritten" page; assert TrOCR is invoked and the higher-confidence result is used.
- Update `tests/test_workflows_hybrid.py` to assert per-block `confidence` field is populated.

## Phase 3 — Real document structure: block-tree IR, DOCX/HTML export (Weeks 4-5)

**Why third:** The user has explicitly asked for structured output (DOCX, HTML). This is also the IR foundation for Phase 4 (translation needs a structured source to preserve structure on output).

### 3.1 New `BlockTree` IR (parallel to existing IR, additive)
File: `src/local_deepl/core/block_tree.py` (new)

Modelled on Docling's `DoclingDocument` and Marker's block tree. Add:

```python
class BlockType(StrEnum):
    TEXT = "text"
    SECTION_HEADER = "section_header"   # with level 1..6
    PARAGRAPH = "paragraph"
    LIST_ITEM = "list_item"             # with depth
    TABLE = "table"                     # first-class
    FIGURE = "figure"                   # first-class, with image bytes
    CAPTION = "caption"
    EQUATION = "equation"               # LaTeX content
    PAGE_HEADER = "page_header"
    PAGE_FOOTER = "page_footer"
    PAGE_NUMBER = "page_number"
    FOOTNOTE = "footnote"
    CODE = "code"                       # fenced code
    KEY_VALUE = "key_value"             # invoice-style

@dataclass
class BlockNode:
    block_id: str                        # ULID, stable across the pipeline
    block_type: BlockType
    bbox: BBox
    text: str
    confidence: float | None
    children: list[BlockNode]            # for tables, lists, nested sections
    parent_id: str | None
    page_idx: int
    section_hierarchy: list[str]         # ["Chapter 1", "1.2 Methodology"]
    metadata: dict[str, Any]

@dataclass
class DocumentTree:
    pages: list[PageTree]                # each page has children[BlockNode]
    sections: list[Section]              # cross-page section tree (h1 -> h2 -> h3)
    tables: list[TableNode]              # flat list, easy export
    figures: list[FigureNode]
    equations: list[EquationNode]
    metadata: dict[str, Any]
```

Keep `DocumentResult` (the legacy IR) for backward compat. `DocumentTree` is the new canonical handoff for export and translation.

### 3.2 Migrate processors to populate the new IR
File: `src/local_deepl/core/processors.py`

Refactor the existing six processors to emit both `DocumentResult` *and* `DocumentTree` shapes from the same input. The processing is unchanged; the IR wrapper is new. Specifically:

- `StructureAnalysisProcessor` -> classify each block into a `BlockType` instead of the current regex-based `kind`.
- `SectionAnalysisProcessor` -> populate `Section` list in `DocumentTree` (currently stored in `page.metadata["sections"]`).
- `LayoutEnrichmentProcessor` -> suppress `PAGE_HEADER` / `PAGE_FOOTER` / `PAGE_NUMBER` from the tree (they're noise for translation). Surface them as a separate `header_footer_blocks` list.
- `TableExtractionProcessor` -> emit a real `TableNode` with `{rows, cols, cells: [[BlockNode]]}` instead of the current `{row, col, block_idx}` cell markers. Implement row/column detection via projection-profile analysis on the existing cell bboxes (cheap, no new model).
- `QualityAnalysisProcessor` -> unchanged (it already annotates `page.metadata["quality"]`).

### 3.3 Routing `figure` label through the grounded backend
File: `src/local_deepl/core/grounded.py`

The grounded parser currently filters out `image` labels. Change: keep them, attach the cropped image bytes (the backend already has the page image; the parser can slice the bbox from it), and emit a `FigureNode` with `image_bytes: bytes`. The image is then embeddable in DOCX/HTML output.

### 3.4 Real DOCX export from `DocumentTree`
File: `src/local_deepl/core/docx_writer.py`

Replace the markdown-only path with a tree walker that emits:

- `SectionHeader` -> `python-docx` paragraph with the matching heading style (`Heading 1`..`Heading 6`).
- `Paragraph` -> body paragraph.
- `ListItem` -> numbered/bulleted list with depth preserved.
- `Table` -> `doc.add_table(rows=N, cols=M)`; each cell receives the inner `BlockNode.text` with the cell's bbox-driven formatting (bold/italic runs from spans if available).
- `Figure` -> `doc.add_picture(BytesIO(figure.image_bytes), width=Inches(6))` followed by the caption as a `caption`-styled paragraph.
- `Equation` -> `python-docx` paragraph with `OxmlElement('m:oMath')` for native Word equations. Fallback: insert a centered image of the LaTeX (rendered via `matplotlib.mathtext`, no extra deps).
- `Code` -> monospace, `Code` style.
- `KeyValue` -> two-column table or a definition list.

### 3.5 HTML export from `DocumentTree`
File: `src/local_deepl/core/html_writer.py` (new)

Borrow Azure Document Intelligence's Markdown element vocabulary:

- `<h1>`..`<h6>` for sections
- `<table>` with full `<thead>`/`<tbody>` and `rowspan`/`colspan` (not pipe-tables)
- `<figure>` + `<figcaption>` for images
- `<code>` for code, `<pre>` for code blocks
- `<math>` (MathML) for equations, with KaTeX-compatible LaTeX inside
- `<!-- PageBreak -->` markers between pages
- `<!-- PageHeader="..." -->` for headers/footers (not rendered, but present)
- Each block carries `data-block-id="..."` and `data-bbox="x0,y0,x1,y1"` for the UI to re-bind after translation.

### 3.6 Block-tree JSON export
File: `src/local_deepl/core/tree_export.py` (new) or extend `src/local_deepl/api/services/document_exports.py`

Add `/api/export/blocktree` (token-bound) that returns the `DocumentTree` as JSON. Match Marker's block-tree JSON shape: `{pages: [{page_idx, width, height, children: [BlockNode...]}, ...], sections, tables, figures, equations, metadata}`. This is the canonical export for downstream tooling.

### 3.7 New API routes
File: `src/local_deepl/api/routers/extraction.py` (extend)

- `POST /api/export/docx` -> now accepts `from_block_tree=true` and walks the tree.
- `POST /api/export/html` -> new endpoint, returns the rendered HTML string + a token-bound artifact id.
- `POST /api/export/blocktree` -> new endpoint, returns the JSON tree.

## Phase 4 — Translation quality: structure-preserving, glossary-aware, dual-translator (Weeks 6-7)

**Why fourth:** Now that we have a real `DocumentTree`, translation can replace text in-place and preserve headings/tables/lists. The sync path also gets all the features the async path had.

### 4.1 Block-tree-aware translation
File: `src/local_deepl/core/translation.py` (refactor)

Add a new function `translate_tree(tree: DocumentTree, target_language: str, settings) -> DocumentTree` that:

1. Walks the tree.
2. For each `BlockNode`, extracts `text` (preserving inline runs if any), translates it as a unit (or a paragraph-level chunk).
3. Writes the translation back to `BlockNode.text` and `BlockNode.metadata["translation"]`.
4. Preserves `BlockType` and `bbox` (no geometry change).
5. Suppresses `PAGE_HEADER` / `PAGE_FOOTER` / `PAGE_NUMBER` (don't translate).
6. Translates `TABLE` cells one at a time; preserves cell ordering.
7. Translates `FIGURE` captions; preserves image bytes.

### 4.2 Sliding-window context
File: `src/local_deepl/core/translation.py`

For each chunk, prepend the last N tokens of the previous chunk's translation as auxiliary context. Mark the boundary clearly so the model knows what's "previous" vs "current". N is a setting (default 400 tokens). This is the single highest-leverage quality win from the WMT 2024 best-practices research.

### 4.3 Document-level entity memory
File: `src/local_deepl/core/translation.py` + new `src/local_deepl/core/entity_memory.py`

Extract a "context block" of all proper nouns, dates, and named entities from the source tree on the first chunk. Persist this in a per-job `EntityMemory` object (in-memory + JSON sidecar). Re-inject into every subsequent chunk's prompt as:

```
CONTEXT (use these names/terms consistently):
- Steve Jobs
- January 9, 2007
- iPhone
```

This fixes the well-known "Tesla → XYZ" mid-document name drift problem.

### 4.4 Glossary management
Files: `src/local_deepl/core/translation.py`, new `src/local_deepl/core/glossary.py`, UI in `src/local_deepl/static/index.html`

- New `glossary.json` schema: `{entries: [{source, target, case_sensitive, notes}]}`. Load from `LOCAL_DEEPL_GLOSSARY` env var (file path) or upload through the UI.
- Glossary is injected into the prompt as a DeepL-style `style_rules` block: `Acme Corp → Acme Société`. Highest match priority: term length descending.
- UI: a new "Glossary" section in the left control panel with a textarea (one entry per line: `source = target`), persisted to localStorage. POST to `/api/glossary` to upload.

### 4.5 NLLB-200 fast translation fallback
File: `src/local_deepl/core/nllb_engine.py` (new)

- Wrap `facebook/nllb-200-distilled-600M` (CPU-friendly) via `transformers`.
- Used when the configured LLM is unavailable, when chunks are short enough that LLM context overhead is wasteful, or when the user picks "fast" mode in the UI.
- Add a `nllb` optional extra in `pyproject.toml`:
  ```
  nllb = [
      "transformers>=4.45",   # shared with trocr
      "sentencepiece>=0.2",
  ]
  ```

### 4.6 Dual-translator pattern
File: `src/local_deepl/core/translation.py`

For high-stakes jobs: translate each chunk twice (different temperatures, or LLM vs NLLB), score both with a lightweight metric (chrF++ via `sacrebleu`, or COMET via the `unbabel-comet` package if the user has GPU), pick the higher-scoring one. Make this opt-in via a setting `dual_translate: bool`.

### 4.7 Quality scoring: chrF++ + COMET
New dep: `sacrebleu>=2.4` (no new install footprint).

- `core/evaluation.py` already has metric helpers. Add `chrf_score(reference, hypothesis) -> float`.
- Add COMET only as an opt-in `comet` extra (large download, GPU-preferred):
  ```
  comet = [
      "unbabel-comet>=2.2",
  ]
  ```
- Translation completion emits a per-chunk quality report: `{chunk_idx, source_chars, translated_chars, chrf, model, attempts}`. Surfaced in the UI's translation tab.

### 4.8 Async translation with progress
File: `src/local_deepl/api/services/progress.py` (extend)

The existing async translation has no progress events. Extend the channel to emit `translate_chunk_complete` events analogous to `block_complete` in Phase 1. The Celery task streams chunks back via Redis pub/sub; the WebSocket forwarder emits each chunk event.

### 4.9 New API routes
File: `src/local_deepl/api/routers/ai.py` (extend)

- `POST /api/translate/tree` -> accepts a `DocumentTree` artifact id + target language, returns the translated tree.
- `POST /api/glossary` -> upload a glossary file.
- `GET /api/translate/quality/{artifact_id}` -> returns the per-chunk quality report.

### 4.10 Tests
- `tests/test_translation_tree.py` for tree round-trip, structure preservation.
- `tests/test_entity_memory.py` for entity extraction and re-injection.
- `tests/test_glossary.py` for term priority, case sensitivity, nested matches.
- `tests/test_dual_translator.py` for the dual-translate + score + pick logic.
- `tests/test_translation_quality_scoring.py` for chrF++ computation.
- Update `tests/test_translation_evaluator.py` for the new evaluator that avoids self-eval bias (configurable evaluator model).

## Phase 5 — Real-time UI: page thumbnails, streaming, confidence heatmap (Week 8)

**Why last:** The plumbing from Phases 1-4 is what makes this UX meaningful. The UI work is mostly additive.

### 5.1 Page thumbnail strip with live status
File: `src/local_deepl/static/index.html` + new `src/local_deepl/static/js/thumbnails.js`

- Render page thumbnails (using PDF.js, already in the bundle) in a vertical strip on the left of the central viewport.
- Each thumbnail is a small `<canvas>`. Subscribe to `block_complete` events; when a page's first block lands, mark its thumbnail as "in progress" (subtle pulse). When its last block lands, mark it "done" (green border).
- Click a thumbnail -> scroll the central viewport to that page.

### 5.2 Live bbox overlay during OCR
File: `src/local_deepl/static/js/app.js` (extend)

- The `block_complete` events from Phase 1.2 feed the SVG overlay in real time. Each new bbox is appended with a 200ms fade-in.
- Color-code by `kind`: text=grey, heading=blue, table=green, figure=violet, equation=orange, low-confidence (<0.75)=red border.
- Hover a bbox -> tooltip with the recognized text + confidence.

### 5.3 Confidence heatmap toggle
File: `src/local_deepl/static/js/workspace_ui.js` (extend)

- A "Show confidence" toggle in the central viewport toolbar.
- When on, fill each bbox with a hue derived from confidence: green >=0.9, yellow 0.75-0.9, orange 0.6-0.75, red <0.6.
- Pair with a "Review low-confidence regions" filter that hides all blocks with confidence >=0.75.

### 5.4 Streaming translation output
File: `src/local_deepl/static/js/app.js` (extend)

- Subscribe to `translate_chunk_complete` events. As each chunk arrives, append it to the right-pane output area.
- Use a `<details>` per chunk so users can expand/collapse to see source vs translation.
- A "Show source" toggle reveals the source text in a side-by-side view (DeepL pattern).

### 5.5 Cancel / retry
File: `src/local_deepl/api/routers/websocket.py` (extend)

- Add a `cancel` event handler. The existing channel can be used bidirectionally.
- Backend: the worker checks a per-channel `cancel_event` between OCR blocks / translation chunks. When set, the current job halts and emits a `cancelled` frame. The user can re-upload and try again.
- For OCR, the partial result (pages processed so far) is saved as an artifact so the user can download it.

### 5.6 Tests
- `tests/test_websocket_cancel.py` for the cancel event flow.
- Update `test_ui.py` Playwright test: run a real job, assert at least 5 `block_complete` events arrive over WebSocket, assert page thumbnails are present, assert confidence heatmap toggle works.

## What is NOT in this plan (and why)

- **Cross-page table continuation detection** — hard problem, weeks of work. Better to ship within-page tables first and add this in a follow-up.
- **PDF re-layout** with semantic markup (Heading 1 vs Body) — PDF is a poor format for reflow. The current sandwich PDF is good enough; structure lives in DOCX/HTML/JSON.
- **Fine-tuning a VLM on handwriting** (LoRA on Qwen2.5-VL) — requires training infra, GPU, dataset. The TrOCR specialist covers the most common case; users can fine-tune their own model and inject it via the existing `ocr_processor=` extension point.
- **Implementing pause/resume** — adds state for little user gain. Cancel + retry from a failed page is the high-value version (Phase 5.5).
- **New translation models beyond NLLB** — the user already runs their own LLM via LM Studio / Ollama. Adding more model options creates UX overhead; the dual-translator + glossary pattern covers the main quality concerns.
- **A new test fixture for the second handwritten sample** — listed as a small task; if no good public-domain source is available, the test ground truth for `examples/handwritten.pdf` is enough for now.
